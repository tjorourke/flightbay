Per-policy testing

  1. Every AuthorizationPolicy gets a Tests tab. Cases are generated from the rule: one that matches, near misses (other value, header absent), interaction with other policies on the same target, and a waypoint bypass case.
  2. Each case has an expected result, so the outcome is pass/fail rather than a raw status code to interpret. "Decided by" names the policy that made the call (from waypoint RBAC log / reach.Explain).
  3. Builds on what exists: Test this rule (prefill), the Test service modal runners (in-mesh curl, temporary pod) and Traffic's Explain. The new part is saving cases and expectations against the policy and re-running them after changes.
  4. The "color: Red" failure is an illustration of the kind of thing a suite catches, not something observed in the recording.
