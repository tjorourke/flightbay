kind: AuthorizationPolicy
metadata:
  name: reviews-methods
  namespace: bookinfo
spec:
  targetRefs:
  - {kind: Service, group: "", name: reviews}
  action: ALLOW
  rules:
  - to:
    - operation:
        methods: [GET, HEAD]
        ports: ["9080"]
Name is editable. Flightbay labels it so it shows as "Managed by Flightbay" and can be undone.

What this does to reviews

  • GET and HEAD keep working.
  • POST, PUT, PATCH, DELETE return 403 from the waypoint.
  • Requests with color: red still get 403: your existing DENY runs first.
⚠
This is the first ALLOW on reviews. Once it exists, anything it does not match is denied. You do not need "Deny by default" as well for L7 traffic.
ℹ
Callers that reach pod IPs directly skip the waypoint and skip this rule. Also add "Block traffic that skips the waypoint"
